# Fase 2.2 — Procesos de Electron

Basado en la skill `.claude/skills/electron-skill/SKILL.md` y en las guías de seguridad de Electron.

## 1. Los cuatro procesos

| Proceso | Cuántos | Privilegios | Qué contiene |
|---|:-:|---|---|
| **Main** | 1 | Node.js completo, acceso al SO | Ventanas, menú, SQLite, sistema de archivos, IPC, generación documental, ciclo de vida |
| **Preload** | 1 por ventana | Aislado; `contextBridge` únicamente | Expone `window.api` como superficie **estática y cerrada**. Sin lógica |
| **Renderer** | 1 (+1 oculto para PDF) | **Sandbox**, sin Node | React 19: pantallas, tablas, formularios. Tratado como código no confiable |
| **utilityProcess** | 0 o 1, bajo demanda | Node, sin acceso al DOM | Cálculo masivo del ejercicio, exportaciones grandes |

## 2. Configuración de la ventana principal

```ts
new BrowserWindow({
  width: 1440, height: 900, minWidth: 1024, minHeight: 700,
  show: false,                       // se muestra en 'ready-to-show': evita el destello blanco
  backgroundColor: '#00000000',
  autoHideMenuBar: false,
  webPreferences: {
    preload: path.join(__dirname, '../preload/index.cjs'),
    contextIsolation: true,          // obligatorio
    nodeIntegration: false,          // obligatorio
    sandbox: true,                   // obligatorio
    webSecurity: true,
    allowRunningInsecureContent: false,
    spellcheck: true,                // hay campos de justificación técnica extensos
    webviewTag: false,
    enableWebSQL: false,
  },
});
```

Los cinco valores marcados como obligatorios se verifican con un test automatizado (`T-A-07`) que
lee el objeto de opciones. No se aceptan excepciones "temporales": son la razón por la que una app
Electron es defendible ante una auditoría.

## 3. Responsabilidades del proceso main

```
src/main/
├── index.ts                  arranque, instancia única, ciclo de vida
├── ventanas/                 creación y estado de ventanas, ventana oculta de PDF
├── menu/                     menú de aplicación y menús contextuales
├── seguridad/                CSP, filtro de permisos, bloqueo de navegación
├── infraestructura/
│   ├── db/                   conexión SQLite, migraciones, respaldos
│   ├── almacen/              archivos adjuntos y fotos
│   └── documental/           ExcelJS, docxtemplater, printToPDF, bwip-js
├── modules/                  MOD-02 … MOD-11 (dominio + casos de uso + repos + IPC)
└── ipc/                      registro de canales, middleware de validación y permisos
```

**El main debe mantenerse liviano en tiempo de CPU** (guía de la skill: "minimize main process
work"). Toda operación de más de ~200 ms se delega al `utilityProcess` o se trocea en lotes con
`setImmediate` entre ellos.

## 4. El preload: superficie estática

El preload **no** expone `ipcRenderer` genérico. Expone un objeto congelado, generado a partir del
contrato compartido:

```ts
// src/preload/index.ts
import { contextBridge, ipcRenderer } from 'electron';
import { CANALES } from '@compartido/ipc/canales';   // lista estática, MOD-00

const api = Object.freeze({
  invocar: (canal: string, entrada: unknown) => {
    if (!CANALES.includes(canal as never)) {
      throw new Error(`Canal IPC no permitido: ${canal}`);   // lista blanca
    }
    return ipcRenderer.invoke(canal, entrada);
  },
  suscribir: (evento: EventoPermitido, cb: (d: unknown) => void) => {
    const oyente = (_: unknown, d: unknown) => cb(d);
    ipcRenderer.on(evento, oyente);
    return () => ipcRenderer.off(evento, oyente);            // devuelve el desuscriptor
  },
});

contextBridge.exposeInMainWorld('api', api);
```

Sobre esta base mínima, el renderer construye un cliente tipado (ver
[2.3 Contrato IPC](2.3_contrato_ipc.md)). Reglas:

- **Nunca** `contextBridge.exposeInMainWorld('electron', { ipcRenderer })`. Sería equivalente a
  desactivar el aislamiento.
- **Nunca** exponer `require`, `fs`, `path` ni `process`.
- La lista de canales es estática y se comparte con el main: no se puede inventar un canal en tiempo
  de ejecución.
- `suscribir` devuelve la función de baja. Los componentes React la usan en el retorno de
  `useEffect`; sin ella se acumulan oyentes al navegar.

## 5. El renderer: qué puede y qué no

| Puede | No puede |
|---|---|
| Renderizar, filtrar y ordenar en memoria lo que ya recibió | Leer o escribir archivos |
| Comprimir una imagen con `<canvas>` antes de enviarla | Abrir la base de datos |
| Formatear números y fechas con `Intl` | Ejecutar código de Node |
| Validar formularios con los mismos esquemas Zod (**conveniencia**) | Confiar en esa validación: el main revalida siempre |
| Pedir cálculos y suscribirse a su progreso | Calcular importes que se persistan |

> El renderer es **código no confiable**, exactamente igual que una página web (guía de la skill).
> Que la escribamos nosotros no cambia el modelo de amenaza: una plantilla `.docx` maliciosa, un
> nombre de archivo con inyección o una dependencia comprometida ejecutan código ahí.

## 6. Ventana oculta para PDF

`printToPDF` necesita un `webContents`. Se usa una ventana oculta reutilizable:

```
crearVentanaPdf()  →  cargar HTML del informe (data: URL o archivo temporal)
                   →  esperar 'did-finish-load' + fuentes cargadas
                   →  webContents.printToPDF({ printBackground: true, pageSize: 'Letter',
                                               margins, landscape según informe })
                   →  escribir el buffer en el almacén
                   →  destruir o reutilizar
```

Detalles que evitan errores conocidos:
- Esperar `document.fonts.ready` antes de imprimir, o los PDF salen con la fuente de respaldo.
- CSS `@media print` propio para cada informe; no reutilizar el CSS de pantalla.
- Tamaño de página **Carta** (estándar colombiano), no A4.
- La ventana de PDF tiene el mismo `sandbox: true`.

## 7. utilityProcess para cálculo masivo

```
main                              utilityProcess ('calculo')
 │  utilityProcess.fork(ruta)  →   abre su propia conexión SQLite (WAL, solo lectura
 │                                 para leer; escribe por lotes en su propia transacción)
 │  postMessage({ejercicioId})  →
 │                             ←   postMessage({tipo:'progreso', hechos, total})
 │  reenvía a renderer                (cada 500 registros o cada 250 ms, lo que ocurra antes)
 │                             ←   postMessage({tipo:'fin', resumen})
 │  kill() si el usuario cancela
```

Por qué `utilityProcess` y no `worker_threads`: `better-sqlite3` es un módulo nativo y su uso desde
varios hilos del mismo proceso es delicado; un proceso separado tiene su propio espacio de memoria y
su propia conexión, y puede terminarse de golpe al cancelar sin dejar el main en mal estado. Además
`utilityProcess` es la primitiva que Electron mantiene para esto.

**Se implementa solo si la medición lo justifica** (`T-D-06`). Si 20.000 bienes se calculan en menos
de 2 segundos en el main, la complejidad no vale la pena y se documenta la decisión.

## 8. Ciclo de vida y eventos que hay que manejar

| Evento | Acción |
|---|---|
| `second-instance` | Enfocar la ventana existente. Nunca abrir dos instancias sobre la misma base |
| `before-quit` | Cerrar la conexión SQLite limpiamente (`db.close()`), o el WAL queda sin consolidar |
| `window-all-closed` | En Windows y Linux, salir. En macOS, comportamiento estándar |
| `render-process-gone` | Registrar el motivo, ofrecer recargar; nunca cerrar en silencio |
| `child-process-gone` | Si cae el `utilityProcess` de cálculo, marcar el cálculo como fallido, no como completo |
| `web-contents-created` → `will-navigate` / `setWindowOpenHandler` | **Bloquear toda navegación externa**; los enlaces externos se abren con `shell.openExternal` previa validación del esquema |
| `certificate-error` | No ignorar nunca |

## 9. Almacenamiento en disco

| Qué | Dónde | Motivo |
|---|---|---|
| Base de datos | `app.getPath('userData')/valuacion.db` | Por usuario del SO, con permisos correctos |
| Respaldos | `userData/respaldos/valuacion-AAAAMMDD-HHmmss.db` | Rotación configurable |
| Adjuntos y fotos | `userData/almacen/<ejercicio>/<bien>/` | CT-14 |
| Plantillas de la entidad | `userData/plantillas/<version>/` | `ANEXO_A` §4.2: editables, versionadas |
| Registros de importación | `userData/importaciones/<fecha>/` | `ANEXO_A` §3.3 regla 6: guardar el original |
| Preferencias de interfaz | `userData/config.json` | No en la base: debe leerse antes de abrirla |
| Secretos (si aparecen) | `safeStorage` de Electron | Cifrado por el sistema operativo |

La ruta base es configurable por línea de comandos (`--datos=<ruta>`) para permitir instalaciones
portables y pruebas, con la verificación de unidad de red de `RG-10`.
