## 3. Entrada aplanada (resuelve CT-10)

El motor no conoce `Bien`, `HojaVida` ni `ClaseActivo`. Recibe:

```ts
type EntradaCalculoBien = {
  bienId: Uuid;
  // de Bien
  estadoActual: EstadoActual;             // BUENO | REGULAR | MALO | INSERVIBLE
  condicionTenencia: CondicionTenencia;   // los no PROPIO se excluyen del patrimonio (RN-02-04)
  // de HojaVida
  fechaAdquisicion: FechaIso | null;      // null → NoCalculable (RN-03-01)
  fechaPuestaServicio: FechaIso | null;
  costoAdquisicionCent: Centavos | null;  // null o 0 → NoCalculable (RN-03-02)
  adicionesMejorasCent: Centavos;         // 0 por defecto
  estadoOperativo: EstadoOperativo;
  vidaUtilTecnicaOverride: number | null; // RN-03-06
  // de ClaseActivo
  esDepreciable: boolean;                 // terrenos: false (RN-06-07)
  vidaUtilContableMeses: number | null;
  vidaUtilTecnicaAnios: number | null;
  subcuentaContable: string;
  // capturado
  obsolescenciaFuncional: boolean;        // RN-05-03
  tieneMantenimientoCorrectivoFallido: boolean;  // ANEXO_C §2.7
  deterioroReconocidoCent: Centavos;      // paso 06
};
```

Construir este objeto es responsabilidad del caso de uso (capa de aplicación), con una única
consulta con `JOIN` por lote de 500. El motor recibe un array y devuelve un array.

## 4. Resultado discriminado

```ts
type Resultado<T> =
  | { estado: 'CALCULADO';     valor: T }
  | { estado: 'NO_CALCULABLE'; motivo: MotivoNoCalculable; detalle: string }
  | { estado: 'NO_APLICA';     motivo: string }        // clase no depreciable
  | { estado: 'ERROR_DATOS';   codigo: string; detalle: string };
```

Esta distinción es la traducción directa de `/especificacion/teoria` y la que más consecuencias tiene:

| Estado | Ejemplo | Efecto en la aplicación |
|---|---|---|
| `NO_CALCULABLE` | Sin costo de adquisición | Bien pasa a `INCOMPLETO`, **se excluye de los totales** (`RN-06-05`), entra en `EN-06-05`, cuenta para `VAL-06-09` |
| `NO_APLICA` | Terreno, clase no depreciable | Se omite de la depreciación pero **sí participa en la consolidación patrimonial** (`RN-06-07`) |
| `ERROR_DATOS` | `fecha_adquisicion > fecha_corte` | Bloqueante `VAL-05-03`; no se calcula con edad negativa (`RN-05-07`) |

> Reportar un bien sin costo con valor cero "distorsionaría el balance" (`RN-06-05`). Que el motor
> devuelva `0` en lugar de `NO_CALCULABLE` sería un error silencioso de miles de millones de pesos.

## 5. Los tres métodos de conteo de meses (`ANEXO_C` §3.3)

```ts
export function contarMeses(inicio: FechaIso, corte: FechaIso, metodo: MetodoConteo): Decimal {
  switch (metodo) {
    case 'mes_completo': {
      const m = (anio(corte) - anio(inicio)) * 12 + (mes(corte) - mes(inicio));
      return new Decimal(dia(corte) < dia(inicio) ? m - 1 : m);
    }
    case 'dias_exactos':
    case 'fraccion_anual': {
      // ANEXO_C §3.3 declara C matemáticamente equivalente a B;
      // se conservan como claves distintas para la presentación en informes.
      const dias = diferenciaEnDias(inicio, corte);
      return new Decimal(dias).div(365.25).mul(12);
    }
  }
}
```

- `mes_completo` devuelve entero; los otros, decimal. El tipo de retorno es `Decimal` en los tres
  casos para no ramificar aguas abajo.
- El método aplicado se persiste **en cada fila** de `CalculoDepreciacion` (`ANEXO_B` §4.3), no solo
  en el parámetro global: permite auditar aunque el parámetro cambie después.
- `diferenciaEnDias` opera sobre fechas civiles `AAAA-MM-DD` mediante días julianos, **sin objetos
  `Date`**: elimina de raíz los errores de zona horaria y de horario de verano.

Cada fila de `ANEXO_C` §2.4 y §3.4 es un test con nombre explícito:

## 7. Reglas de redondeo (`ANEXO_C` §8)

```ts
// RED-06: al más cercano, desempate hacia arriba
Decimal.set({ rounding: Decimal.ROUND_HALF_UP });
```

| Regla | Implementación |
|---|---|
| `RED-01` intermedios a máxima precisión | El motor nunca redondea dentro de una fórmula |
| `RED-02` redondear solo al persistir y al presentar | Una única función `aCentavos(decimal)` en la frontera |
| `RED-03` índices y factores con 4 decimales | `aX10k(decimal)` |
| `RED-04` dinero con 2 decimales | Centavos |
| `RED-05` **los totales suman los valores redondeados de detalle** | Las agregaciones se hacen con `SUM()` sobre la columna de centavos ya redondeada, nunca recalculando desde los originales |
| `RED-06` medio hacia arriba | Configuración global de `decimal.js` |

`RED-05` es la regla que evita la pregunta más incómoda de una auditoría: "el total dice X, pero sus
filas suman Y".

## 8. Orden de ejecución (`ANEXO_C` §10)

```
1. Validar parametrización del ejercicio       → si falla, no se calcula nada
2. Por cada bien (lotes de 500):
   2.1 Validar completitud de datos económicos
   2.2 Obsolescencia        (§2)
   2.3 Depreciación         (§3)
   2.4 Aplicar deterioro registrado (§4)
   2.5 Valuación sugerida   (§5)
3. Agregar por clase y subcuenta
4. Incorporar valores de inmuebles (§6)
5. Consolidar              (§7)
6. Verificar cuadre en tres niveles (§7.1)
7. Persistir con marca de tiempo y método aplicado
```

Los pasos 2.2 a 2.5 son puros y podrían paralelizarse; **no se paraleliza en v1** hasta que la
medición (`T-D-06`) demuestre que hace falta. La medición primero, la optimización después.

## 9. Disparadores de recálculo (`ANEXO_C` §10)

Cambiar cualquiera de estos campos invalida los cálculos del ejercicio y **debe** registrarse en
bitácora:

`fecha_corte` · `vida_util_contable_meses` · `vida_util_tecnica_anios` ·
`vida_util_tecnica_override` · `costo_adquisicion` · `adiciones_mejoras` · `fecha_adquisicion` ·
`fecha_puesta_servicio` · `clase_activo_id` · cualquier `ParametroCalculo` de cálculo.

Implementación: los cálculos guardan `parametros_hash` y `entrada_hash`. Al abrir cualquier
pantalla de cálculo, si el hash actual no coincide con el persistido, se muestra el aviso
**"cálculo desactualizado"** con el botón de recalcular. Nunca se muestra una cifra obsoleta como
si fuera vigente.

```

P3  valor_neto_libros ≤ saldo_final_ajustado

P5  factor_vida_restante ∈ [0, 1]
```

esperado se modifica sin una entrada en `/proyecto/gestion/bitacora.md` que lo justifique**
(mitigación de `RG-01`).
