# Fase 1.2 — Descomposición en módulos

## 1. Criterio de descomposición

El sistema **no** se parte por capas técnicas (controladores / servicios / repositorios), sino por
**dominio de negocio**, siguiendo la estructura que `/especificacion/teoria` ya impone. Razones:

1. `/especificacion/teoria` está organizada por paso, y cada paso tiene sus propias entidades, reglas, validaciones
   y entregables. Partir por dominio hace que un requisito `RF-05-03` se localice en un solo lugar.
2. Un monolito modular con fronteras de dominio puede crecer sin volverse una bola de barro, y
   permitiría extraer un módulo si algún día se necesita (por ejemplo, el módulo de captura).
3. Reduce el acoplamiento: el módulo de bajas no necesita saber cómo se importa un Excel; consume
   el componente transversal.

## 4. Reglas de dependencia (verificadas automáticamente)

Se aplican con `eslint-plugin-boundaries` o `dependency-cruiser` en CI (`T-A-04`). Violarlas rompe
la compilación.

| # | Regla |
|:-:|---|
| D-1 | `MOD-00` no importa de ningún otro módulo. |
| D-2 | `MOD-06` (motor de cálculo) importa **solo** de `MOD-00`. No conoce SQLite, ni `fs`, ni Electron, ni React. |
| D-3 | Un módulo de dominio (`MOD-02`…`MOD-11`) nunca importa de otro módulo de dominio **de un paso posterior**. Las dependencias van en el sentido del flujo del proceso. |
| D-4 | Ningún módulo de dominio importa de `MOD-12`; `MOD-12` se inyecta como puerto. |
| D-5 | El código del **renderer** nunca importa `MOD-01` ni acceso directo a datos. Solo `MOD-00` (tipos) y el cliente IPC. |
| D-6 | Nada en `src/main` importa de `src/renderer` ni viceversa; el único puente es `MOD-00` + preload. |

> **Por qué D-2 es la regla más importante:** el motor de cálculo es el componente cuyo error tiene
> consecuencias legales. Mantenerlo puro lo hace 100% testeable sin base de datos, sin Electron y sin
> mocks, y permite ejecutar los 15 casos de `ANEXO_C` §11 en milisegundos, en cada commit.

## 5. Fronteras: qué expone cada módulo

Cada módulo publica un único `index.ts` (barrel) con su API pública. Todo lo demás es privado.

```
src/main/modules/depreciacion/
├── index.ts              ← única superficie pública del módulo
├── casos-uso/            calcularDepreciacionEjercicio.ts, registrarDeterioro.ts …
├── repositorio/          calculoDepreciacion.repo.ts, deterioro.repo.ts
├── validaciones/         val-06.ts   (VAL-06-01 … VAL-06-10)
└── ipc/                  handlers.ts (registra los canales `depreciacion:*`)
```

`eslint` prohíbe importar rutas profundas de otro módulo (`modules/x/repositorio/...`).
