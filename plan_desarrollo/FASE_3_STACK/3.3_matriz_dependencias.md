# Fase 3.3 — Matriz de dependencias

Cada dependencia declara: para qué sirve, qué requisito de `/Teoria` habilita, dónde se ejecuta, qué
riesgo trae y por qué alternativa se sustituiría si desapareciera.

**Regla de admisión.** Ninguna dependencia entra al proyecto sin una fila en esta tabla. Añadir una
dependencia es una decisión, no un `npm install`.

---

## 5. Reglas de gobierno de dependencias

| # | Regla |
|:-:|---|
| G-1 | Toda dependencia nueva requiere una fila en esta matriz **antes** de instalarse |
| G-2 | Versiones **fijadas exactas**; `package-lock.json` versionado |
| G-3 | Toda dependencia del renderer o compartida se audita contra `R-05` ([3.2](3.2_compatibilidad.md) §5.3) |
| G-4 | Las dependencias de infraestructura se ocultan tras un puerto (`MOD-12`): sustituir ExcelJS no debe tocar el dominio |
| G-5 | `npm audit` en CI. Vulnerabilidad alta o crítica bloquea la publicación de una versión |
| G-6 | Los módulos **nativos** requieren aprobación explícita: cada uno multiplica el riesgo `RG-06`. **Autorizado exactamente uno: `better-sqlite3`.** Cualquier otro exige un ADR nuevo |
| G-7 | Ninguna dependencia hace peticiones de red en tiempo de ejecución (`RNF-08`). Se verifica en E2E con la red bloqueada |
| G-8 | Se revisa la licencia de cada dependencia; se evita GPL/AGPL en código distribuido |

## 6. Puntos únicos de fallo

| Dependencia | Por qué es crítica | Plan si desaparece |
|---|---|---|
| `better-sqlite3` | Toda la persistencia | Migrar a `node:sqlite`: misma semántica SQL, cambia solo el adaptador. La capa de repositorio lo aísla |
| `decimal.js` | Exactitud monetaria | `big.js`, con la misma interfaz mínima que usamos. Aislado en `motor/dinero.ts` |
| `docxtemplater` | Los 8 entregables Word | Impacto alto: obligaría a reconstruir los documentos con `docx`, abandonando las plantillas del cliente. Es la dependencia con mayor riesgo de sustitución (`RG-08`) |
| Electron | Todo | Sin plan. Es una restricción del cliente (`R-03`) |

> **Conclusión operativa:** el aislamiento tras puertos (`G-4`) convierte la sustitución de casi
> cualquier dependencia en un trabajo de un adaptador. La única excepción real es `docxtemplater`,
> porque su formato de plantilla es parte del contrato con el cliente. Por eso `T-G-04` audita las
> plantillas Word **antes** de construir el generador.
