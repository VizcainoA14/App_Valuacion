# Fase 4.1 — Estructura de carpetas

## 1. Raíz del repositorio

La aplicación se construye en `/app`, hermana de las carpetas documentales que ya existen. Así el
código convive con su especificación sin mezclarse.

```
App_Valuacion/
├── Teoria/                      ← especificación funcional (NO se toca desde el código)
├── Plantillas_Valuacion_Activos/ ← plantillas .xlsx y .docx de referencia
├── plan_desarrollo/             ← este plan
├── gestion_proyecto/            ← estado, roadmap, bitácora
├── .claude/                     ← skills y configuración de sesión
├── CLAUDE.md                    ← protocolo de inicio para agentes
└── app/                         ← ★ LA APLICACIÓN
```

## 3. Decisiones de estructura y su motivo

| Decisión | Motivo |
|---|---|
| `src/compartido` es un directorio de primer nivel, no `src/main/shared` | Refuerza que el motor y los tipos **no pertenecen** al main. Facilita verificar la regla D-2 |
| El renderer espeja `src/main/modules` en `src/renderer/features` | Un requisito `RF-05-03` se localiza en dos rutas predecibles, no en veinte |
| `componentes/` (sin negocio) separado de `features/` (con negocio) | Impide que un botón conozca la regla `RN-06-03`. Sin esta separación, el sistema de diseño se contamina y deja de ser reutilizable |
| `formato/` como carpeta propia | `RED-05` solo se cumple si el redondeo de presentación ocurre en un único lugar |
| `recursos/` separado de `build/` | `recursos/` se empaqueta y la app lo lee en ejecución; `build/` solo lo usa el instalador |
| `docs/` dentro de `app/` | Son artefactos generados por scripts del código, no documentación de negocio (esa vive en `/Teoria`) |
| Cuatro `tsconfig` | Main, preload, renderer y compartido tienen `lib` y `target` distintos. Un único `tsconfig` permitiría usar APIs de Node en el renderer |

## 4. Anatomía de un módulo de dominio

Todos idénticos. Un desarrollador que ya vio uno sabe navegar los once.

```

├── index.ts                      ← única superficie pública
├── casos-uso/
│   ├── calcularDepreciacionEjercicio.ts
```

## 5. Convenciones de nomenclatura

| Elemento | Convención | Ejemplo |
|---|---|---|
| Componentes React | `PascalCase.tsx` | `TablaDatos.tsx` |
| Hooks | `camelCase.ts` con prefijo `use` | `useCalcularEjercicio.ts` |
| Casos de uso | `camelCase.ts`, verbo primero | `calcularDepreciacionEjercicio.ts` |
| Repositorios | `<entidad>.repo.ts` | `calculoDepreciacion.repo.ts` |
| Tablas SQL | `snake_case` singular, igual que `ANEXO_B` | `calculo_depreciacion` |
| Canales IPC | `<modulo>:<accion>` | `depreciacion:calcularEjercicio` |
| Tests | junto al código, `.test.ts` | `depreciacion.test.ts` |

**El idioma del código es el español**, igual que `/Teoria`, los enums y los nombres de tabla. Un
sistema con `Bien`, `HojaVida` y `CalculoDepreciacion` en español y `getById` en inglés obliga a
traducir mentalmente en cada lectura. Excepciones: las APIs de las librerías y las palabras clave de
TypeScript, que son lo que son.

## 6. Alias de importación

```jsonc
{
  "@compartido/*": ["src/compartido/*"],
  "@main/*":       ["src/main/*"],
  "@renderer/*":   ["src/renderer/*"],
  "@motor/*":      ["src/compartido/motor/*"]
}
```

Configurados en los cuatro `tsconfig` y en `electron.vite.config.ts`. `eslint-plugin-boundaries` usa
estos alias para aplicar las reglas D-1 a D-6: por ejemplo, un archivo bajo `@motor/` que importe
`@main/` es un error de compilación.
